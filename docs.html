Documentação do Projeto IHC

Aplicação interativa demonstrando paradigmas de Interação Humano-Computador: CLI, Formulários, Manipulação Direta e Dashboard em tempo real.

O Projeto IHC é uma Single Page Application (SPA) que exemplifica quatro paradigmas distintos de interação humano-computador dentro de um fluxo unificado. Cada tela apresenta um estilo de interação diferente, conectados por um servidor Node.js/Express com comunicação em tempo real via Socket.IO.

💡
Este projeto foi desenvolvido como demonstração acadêmica para a disciplina de Interação Humano-Computador, explorando conceitos de usabilidade, acessibilidade e paradigmas de interface.

01 Início Rápido

Pré-requisitos

  • Node.js ≥ 20.x
  • npm ≥ 10.x (incluso no Node.js)

Instalação

# Clonar o repositório
git clone https://github.com/gustavo7huan7-png/Projeto-IHC-.git
cd Projeto-IHC-

# Instalar dependências
npm install

# Iniciar o servidor (produção)
npm start

# Iniciar com hot-reload (desenvolvimento)
npm run devTerminal

Acessar a Aplicação

Após iniciar o servidor, acesse http://localhost:3000 no navegador.

✅
O servidor exibirá no terminal a URL de acesso e confirmação de que o Socket.IO está ativo.

03 Visão Arquitetural

A aplicação segue uma arquitetura cliente-servidor com SPA no front-end, API REST para operações CRUD e WebSockets (Socket.IO) para comunicação em tempo real.

Diagrama de Arquitetura
🖥️ Browser (SPA)
index.html + JS Modules
↕ HTTP / WebSocket
🚀 Express.js
Servidor HTTP + Static
🔌 Socket.IO
Eventos em Tempo Real
↕ In-Memory
💾 Armazenamento
Arrays em memória (RAM)
⚠️
Armazenamento volátil: Os dados são armazenados em memória (arrays JavaScript). Ao reiniciar o servidor, todos os dados de usuários e mensagens são perdidos. Isso é intencional para um projeto demonstrativo.

05 Fluxo de Dados

O fluxo do usuário é sequencial, passando por cada paradigma de interação:

Fluxo do Usuário
Tela 1 — CLI
/setnome, /setcurso, /setidade
→
Tela 2 — Form
Confirmar / Editar dados
→
Tela 3 — Chat
Mensagens em tempo real
Tela 4 — Dashboard
Acessível via /gestorsite

Estado Global (estadoGlobal)

Um objeto JavaScript compartilhado entre todos os módulos armazena o estado do usuário atual:

const estadoGlobal = {
  nome: null,      // String — definido via /setnome
  curso: null,     // String — definido via /setcurso
  idade: null,     // Number — definido via /setidade
  id: null,        // String — gerado pelo servidor ou local
  telaAtual: 'tela-1'
};JavaScript

Persistência de Sessão

O estado é persistido via localStorage para sobreviver a recarregamentos da página. As funções responsáveis são:

  • salvarSessao() — Serializa o estado para localStorage
  • carregarSessao() — Restaura o estado ao carregar a página
  • limparSessao() — Remove os dados salvos (logout ou exclusão)

06 Tela 1 — Terminal CLI

Paradigma de Interface de Linha de Comando. O usuário interage digitando comandos textuais para definir seus dados (nome, curso, idade).

Comandos Disponíveis

Comando Argumento Descrição
/help — Exibe a lista de comandos disponíveis
/setnome "Nome" Define o nome do usuário (2–60 chars)
/setcurso "Curso" Define o curso do usuário
/setidade "Idade" Define a idade (16–55)
/continuar — Valida dados e avança para Tela 2
/limpatela — Limpa o terminal
/telabin — Easter egg — efeito Matrix Rain (5s)
/apagarsite — Easter egg — progress bar + "acesso negado"
/gestorsite — Acesso direto ao Dashboard (Tela 4)

Funcionalidades Técnicas

  • Autocomplete — Sugestão em tempo real ao digitar /, ativável por Tab ou clique
  • Histórico — Navegação por comandos anteriores com setas ↑ / ↓
  • Parser de comandos — Suporta argumentos com e sem aspas
  • Animação de título — Efeito "typewriter" letra por letra ao carregar
  • Comandos clicáveis — Links no output que preenchem o input ao clicar
  • Responsividade touch — Compatível com teclados virtuais (Gboard, iOS)

07 Tela 2 — Formulário de Confirmação

Paradigma de Formulários. Os dados inseridos via CLI são pré-preenchidos e o usuário pode editar antes de confirmar.

Campos e Validação

Campo Tipo Regras Feedback Visual
nome text 2–60 caracteres ✓ Nome válido / ✗ Inválido
curso text 2–80 caracteres ✓ Curso válido / ✗ Inválido
idade number Inteiro entre 16–55 ✓ Idade válida / ✗ Inválida

Comportamento

  • Validação em tempo real — Cada campo valida a cada keystroke (input event)
  • Feedback visual — Classes CSS .valid / .invalid no wrapper do campo
  • Shake animation — Ao tentar submeter com dados inválidos, o card treme
  • Foco inteligente — Ao entrar, foca no primeiro campo vazio ou no botão de confirmar
  • PUT /api/usuarios/:id — Envia os dados editados ao servidor

Design

Utiliza glassmorphism com partículas decorativas flutuantes, card centralizado com bordas semi-transparentes e efeito de blur no background.

08 Tela 3 — Chat em Tempo Real

Paradigma de Manipulação Direta. Chat bidirecional em tempo real via Socket.IO, com visual inspirado no WhatsApp.

Funcionalidades

  • Mensagens em tempo real — Enviadas e recebidas via WebSocket
  • Optimistic UI — Mensagem aparece instantaneamente antes da confirmação do servidor
  • Histórico — Ao conectar, o servidor envia as últimas mensagens
  • Reconexão automática — Socket.IO gerencia reconexões transparentemente
  • Indicador de status — "Online", "Reconectando...", "Sem conexão"
  • Bloqueio de usuário — Se banido pelo Dashboard, o input é desabilitado
  • Modo offline — Informa que a mensagem não foi enviada

Eventos Socket.IO (Cliente)

Evento Direção Payload
chatMessage ↑ emit { id, nome, texto, hora }
chatMessage ↓ on { id, nome, texto, hora }
historicoMensagens ↓ on Array<mensagem>
pedirHistorico ↑ emit —
usuarioAtualizado ↓ on { id, status, ... }

09 Tela 4 — Dashboard Administrativo

Painel de administração do site. Permite gerenciar usuários cadastrados e espelhar mensagens do chat.

Aba "Usuários"

  • Listagem de cards — Cada usuário é exibido em um card com nome, curso, idade, ID e status
  • Excluir usuário — Remove o usuário via DELETE /api/usuarios/:id + Socket.IO
  • Bloquear/Desbloquear — Alterna o status via PUT /api/usuarios/:id/status
  • Animação de entrada — Cards aparecem com delay escalonado
  • Atualização reativa — Escuta eventos Socket.IO para atualizar em tempo real

Aba "Chat"

  • Espelho do chat — Exibe mensagens do chat em formato simplificado para monitoramento
  • Auto-scroll — Rola automaticamente ao receber novas mensagens

Body

12 WebSockets — Eventos Socket.IO

A comunicação bidirecional em tempo real é gerenciada pelo Socket.IO. Abaixo, todos os eventos do servidor:

Eventos Emitidos pelo Servidor

Evento Destino Payload Quando
WS historicoMensagens socket mensagem[] Ao conectar ou pedir histórico
WS chatMessage broadcast { id, nome, texto, hora } Nova mensagem de chat
WS usuarioCadastrado io (todos) usuario POST /api/usuarios
WS usuarioAtualizado io (todos) usuario PUT em dados ou status
WS usuarioDeletado io (todos) { id } DELETE de usuário

Eventos Recebidos pelo Servidor

Evento Payload Ação
chatMessage { id, nome, texto, hora } Armazena e retransmite para outros
deletarUsuario { id } Remove e emite usuarioDeletado
atualizarUsuario { id, isBanned } Altera status e emite usuarioAtualizado
pedirHistorico — Envia historicoMensagens

13 Design Tokens

O projeto utiliza um design system baseado em CSS Custom Properties, definido em global.css. Os tokens garantem consistência visual entre todas as telas.

Paleta de Cores

Token Valor Uso
--cli-bg #000000 Fundo do terminal CLI
--cli-green #00FF00 Texto principal do CLI
--form-bg #0f0f1a Fundo do formulário
--form-accent #7C4DFF Cor principal do formulário
--chat-accent #00A884 Cor de destaque do chat
--chat-bubble-self #005C4B Bolha de mensagem própria
--dash-danger #FF5252 Ações destrutivas no dashboard

Tipografia

  • Sans-serif: 'Inter' — Usado em formulários, chat e dashboard
  • Monospace: 'Share Tech Mono' — Usado exclusivamente no terminal CLI

Espaçamento

Escala de 4px consistente: --space-xs (4px), --space-sm (8px), --space-md (16px), --space-lg (24px), --space-xl (32px), --space-2xl (48px).

Acessibilidade

  • Touch targets: Mínimo de 44px (--touch-min) para botões e inputs
  • Focus visible: Outline de 2px solid var(--form-accent)
  • Labels visualmente ocultos: Classe .visually-hidden para screen readers
  • Roles ARIA: role="log" e aria-live="polite" no terminal e chat

15 Deploy

Railway

O projeto está hospedado na Railway:

  1. Utilizando o repositório GitHub para Railway
  2. A Railway detecta automaticamente o package.json
  3. O comando de start (npm start) é executado automaticamente
  4. A variável PORT é injetada pela Railway
ℹ️
Os arquivos CSS e JS utilizam cache-busting (?v=1.2) e headers no-cache para garantir que atualizações sejam refletidas imediatamente após deploy.

Docker (Alternativa)

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]Dockerfile
